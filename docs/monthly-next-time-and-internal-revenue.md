# Monthly NEXT time and internal revenue

The Hub enriches both month and fiscal YTD report periods. Prior-year periods use the same pipeline. NEXT source time is read from the published generation, completed imports and approved valid rows. Absence and OB supplements are excluded from worked hours. Physical repetitions within one export survive, while equivalent copies from another export collapse. Project-to-unit resolution uses canonical Hub identities and dated unit membership/collection relations; uncertain mappings are grouped under the existing canonical Övrigt collection, with an explicit unresolved-hour count rather than a guessed equipment identity.

NEXT project work and workshop repair work are separate rows. They are never added to TransPA driver time or driving utilization. The source definitions state this explicitly. This prevents double counting people present in both systems and prevents repair work inflating chauffeur productivity. Units receive separate NEXT project/workshop hour fields where canonical membership is unique.

Workshop debits already posted in NEXT (4630, internal AO/workshop evidence) remain Service & repair, once, within existing costs. A separate cost subtotal and project-level evidence link the imported hours with those debits. Zero-priced rows alone do not create costs. Explicitly approved, dated cost profiles may create provisional salary-based repair costs where actual project/month workshop debits are absent. Missing actual debits remain flagged and provisional amounts are shown separately in web/PDF/Excel. Future publication suppresses the provisional amount when the corresponding actual debit exists. The debit can cover more than labor; no hourly price is inferred by dividing it by hours.

Internal billing is a **part of** the reported revenue, not an addition. It is placed directly below the revenue metric in web/PDF/Excel. It uses the same all-registered-revenue rule as the report total, including internal rows whose original invoice status is not Invoiced. The original status split is retained in the Hub payload. Therefore it can differ from the Overview's explicitly Invoiced-only internal card. Revenue, cost and result remain unchanged.

Validation: source/OB/absence separation, prior-year missing evidence, canonical unit and project filtering, repeated export versus repeated physical row, unchanged prepared monetary facts, private-helper permissions, report financial invariance, PDF rendering and Excel round-trip.

The separately approved FY25/26 historical workbook is now imported with original physical rows and separate approval metadata. Canonical person matching uses existing NEXT name keys or unique exact canonical names; unmatched people remain source-only Hub people. No fuzzy person merge or historical workshop role is inferred. The historical file has no role column, so it remains project time.

Dated private cost profiles freeze the approved 33,000 monthly salary and existing 40-hour/1.5-overtime/load-factor assumptions for FY25/26. Current repair estimates retain the current 34,000 assumption. Native TransPA time covers NEXT time per canonical person and day; only the positive daily gap is costed. OB supplements do not add worked hours. Explicit overtime and incremental normal hours above weekly capacity receive the multiplier. Weekly capacity accounts for existing native hours without repricing them.

Corresponding NEXT 7010 ARB costs are offset within project/month, bounded by source cost and the file-hours/reference-hours ratio. Reference hours are counted per original accounting fact, once before recipient allocation. Partial months retain the uncovered reference cost. Raw accounting amounts remain immutable. Positive estimates and negative offsets carry profile/source evidence, use existing dated cost-allocation rules, and are published once per generation/profile. Future report builds run the publisher before normal shared-cost allocation. Revenue is unaffected.

Cold comparison preparation exceeded the authenticated default 8-second limit. The monthly report RPC now has a dedicated 25-second timeout (supported by PostgREST function configuration), below the UI timeout; other endpoints retain their existing limits. Internal-customer lookup now uses a partial period index (measured lookup 5.1 s → 0.28 s), month facts push exact date bounds into the existing period index, and repair debits reuse the already materialized financial scope. These preserve values and avoid loading all fiscal-year evidence for one monthly subtotal. A missing historical NEXT import returns without reading costs.
