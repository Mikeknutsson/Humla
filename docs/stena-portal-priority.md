Owner-approved portal Excel amounts supersede matching Workify transport revenue. Settled uses Pris SEK directly. History uses H+I as line price for pallets, IBC, small boxes, drums, bags and lids; count multiplies only confirmed flak/container/compactor types. Unknown type with a single carrier has the same line amount. Unknown multi-carrier type or missing required count remains unresolved, and linked Workify is retained. Known zero price remains zero. Source inputs and previous computed amount are retained privately. Carrier type must be supplied to the private import adapter.

Private file observations retain SHA-256 and row provenance. Only complete files participate. Canonical TransportRevenue objects and hub_identity_keys own journey identity; booking references stay in the adapter. Settled has priority over history for future overlapping bookings. Exact date-valid economic-unit registration mapping is used; unknown registrations go to the configured hired-vehicle unit. No fuzzy registration corrections.

Workify matching is restricted to the two Stena customer names and exact booking references in Littranummer/ArtikelKommentar. Multiple booking references suppress the aggregate Workify row once. Components touching an unresolved portal amount are blocked together. Unmatched Workify remains included. Superseded derived facts are backed up privately; raw imports are never deleted. Repeat projection restores the backed-up baseline before recomputing. Audit rows remain as history even when a newly unresolved portal amount causes Workify to be restored. Display facts update atomically; financial totals reconcile. Nightly projects before allocation; monthly overhead is recalculated after corrections. Revenue cutoff includes complete priced Stena imports.

Rollback SQL tests cover price basis, missing counts, unknown types, replay conservation, priority exclusion, duplicate journey prevention, display equality, fallback and authorization. Source workbooks and raw data are private. Similar date/vehicle/amount is only a duplicate candidate, never sufficient to delete a valid transaction. High counts on rows still classified as flak require business review; the carrier-type rule does not prove those inputs are correct. Payment forecast uses a separate ingestion path and is not covered by this KPI projector.
